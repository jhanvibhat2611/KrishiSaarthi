Recording and fairness
Both arms must record exact submitted prompt/hash, raw output (including partial
failures), parsed status, citation validity, finish reason, generated token count,
chat-template input count/hash, generation latency, model/config fingerprints and
peak memory. Record retrieval and model-load latency separately from decode time;
report end-to-end costs too. On failure, unavailable measurements stay null, with
failure stage recorded. Capture backend metrics in finally, including prefill errors
that occur before MLXTextBackend's current try/finally. No current adapter wiring
is provided, and exact token counts are not measured in this milestone.

Equal calls/output caps do not equalize input tokens, prefill time, total compute
or prompt difficulty. RAG adds evidence and citation-formatting burden. Retain the
common prompt prefix and separately hash the source-policy instructions. Record
both prompt counts and RAG-minus-Direct difference; do not pad Direct artificially.
At future execution, prefer serialized phases: retrieve/cache validated evidence
locally, unload E5, then load Qwen once for paired generation. This avoids retaining
Torch and MLX model weights together. Neither stage is executed here.

Primary denominators: all 24 planned question-arm slots (12 per arm; 4 per language
per arm), including unattempted slots and failed generations. Also report 12 paired
cases, attempted calls, completed responses, structured-valid responses, usable
answer drafts, insufficient/uncertain outputs and each failure category separately.
A completed malformed JSON string is a response, not valid output. A citation
failure can follow valid JSON but is not a usable sourced draft. Never remove
failure cases from the headline denominator; conditional rates must name their
smaller denominator. Token/time totals need observed-count denominators when nulls
exist. No current fake numerator is combined with the 24-case proposal denominator.

  bitwise guarantee. Structural citations are not factual verification.
- .venv has Torch retrieval; .venv-rag has MLX. Do not silently merge dependencies.
  A later approved runner should bridge validated local records between processes
  or explicitly verify a compatible environment; no environment change here.
- The fake RAG builder accepts synthetic text only. A future reviewed adapter must

- Both prompts must fit Qwen's template budget; no real tokenization has run.
  Retrieval completeness is not assumed from five hits. No gold-guided selection.
- No human-review scorer, automatic gold exporter or real comparison runner is
  introduced. Human fields stay blank. The twelve cases are development material,
  not an independent benchmark and not twelve independent information needs.
