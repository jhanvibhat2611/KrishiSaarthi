Reuse and actual connections
- QwenDecoder wraps an ALREADY LOADED instance of the existing MLXTextBackend.
  It checks Qwen/tokenizer revision, pinned package configuration, temperature,
  seed, context, batch and chat-template settings. It does not load, download or
  initialize a model. Its decode method delegates a single 384-token call to the
  existing backend. The original two-stage generator is never called or changed.
- E5EvidenceAdapter wraps the existing ALREADY LOADED LocalRetrieval service. It
  checks cache/model/corpus identity, delegates Top-5 retrieval to service.search,
  checks every result against trusted passage records and validates source bytes,
  canonical text, offsets and page files via existing validate_corpus. No index
  operation, model loading or gold/reference lookup is implemented here.
- PairedComparison receives the narrow Question type, an EvidencePack and source
  documents. It uses existing Direct system instructions/prompt construction and
  RAG_SYSTEM; only the RAG user message includes sources and qualifications.
  Both prompts use exactly the same question/language. The Direct decoder call
  gets no evidence pack, reference answer, expected evidence or answerability.
- The RAG message assigns E1..E5 in retrieved order. Canonical citations are
  application-managed using existing resolve_answer and CitationValidator.
  A real-mode pair additionally requires exact complete frozen passage records
  (fixed 15-passage fingerprint) and checks every selected record against them.
  Synthetic fixture offsets are never substituted for PAU canonical offsets.
- Raw outputs undergo existing strict duplicate-key/JSON/status/schema validation.
  Resolved citations include source document, page, hashes, exact offsets and
  qualifications. Structural validity never establishes factual support.

Accounting and failures
- Preflight BOTH template-tokenized prompts before any decode. Each may use at most
  7808 input tokens plus 384 reserved output tokens. No truncation or passage removal.
  Preflight failure blocks both planned slots, with zero attempted decode calls.
- A slot becomes attempted immediately before decode; runtime failure still counts.
  Each planned case may be submitted once per comparison instance. Repeat attempts
  are rejected; no retries. Runtime or telemetry failures halt subsequent calls.
- Raw output/partial output survives malformed JSON, schema/citation failures,
  length exhaustion and runtime failures. Error messages are not logged or copied
  into shareable reports. Unsafe/unrecognized exceptions are runtime failures.
- Per-call application latency surrounds decode and validation; backend decode
  metrics are separately retained. Exact template input counts/hashes, generated
  token counts, finish reason and backend memory/runtime metrics are recorded.
  Partial-failure metrics unavailable from the backend stay null, not invented 0.
  Completed responses with missing generated-token/runtime metrics fail telemetry
  validation. Changed input counts/hashes or invalid output counts halt the run.
- All 24 planned slots remain the primary denominator, with 12/arm and 4/language/
  arm. Actual model attempts and mock decode calls are distinct. Unattempted slots,
  completed responses, answer drafts, withholding and categorized failures remain
  separate. Completion does not imply valid JSON or factual correctness.
- Each case records Direct/RAG prompt counts and their difference. Equal output
  caps do not establish equal input budgets, prefill costs or total compute.
- Blank human-review fields reuse the existing rubric. Direct supplied-evidence
  citation applicability is N/A. RAG citation review is separate from factual
  support. Externally verified false and its verification reference remain blank;
  unsupported by this corpus is not automatically externally false.
