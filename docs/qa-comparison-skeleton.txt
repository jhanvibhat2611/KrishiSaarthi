Direct LLM versus RAG: isolated FAKE-OUTPUT plumbing

This is not a real comparison or model integration. No model backend is imported,
constructed or called. The CLI has no model, dataset, reference or real-mode option.
Existing generation, retrieval runners and UI remain unchanged.

Run the built-in invented fixture (prints JSON; writes nothing by default):
  PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv-rag/bin/python scripts/run_fake_qa_comparison.py
Optionally add --output data/<fresh-fake-comparison-directory> to save fake results
and an EMPTY human-scoring.pending.json. Existing directories are rejected.

Contracts
- Direct prompt receives only text and language through the narrow Question type.
  It receives no retrieved text, source IDs, reference answers or answerability.
- RAG prompt receives the same question plus synthetic evidence text and local
  handles. No references, required-fact rubric or gold labels enter either prompt.
- SyntheticCase/Question/SyntheticEvidence reject extra metadata fields. Only the
  built-in fixture is accessible through the CLI; no agricultural drafts are read.
  Types and whitelisting prevent accidental field leakage, not arbitrary secrets
  deliberately embedded by a caller inside question/evidence text.
- The paired case/question identity, prompt versions/hashes, evidence fingerprint
  and fixed intended budgets are saved. Budgets are metadata ONLY in fake mode:
  no tokenization, truncation, real latency or memory measurements are claimed.
- Supplied strings undergo strict duplicate-key/JSON/status/schema checks. Maximum
  two claims. Missing/unknown/duplicate RAG handles are rejected; source references
  are application-resolved synthetic intervals. Raw invalid outputs are retained.
  FakeFailure permits explicit runtime/exhaustion/repetition fixtures, clearly
  labeled simulated. No repairs, retries or confidence estimates.

Scoring separation
Both arms expose the same empty fields for human correctness, completeness,
abstention appropriateness, language, conditions/units and unsupported claims.
Reference hash, reference approval, reviewer identity and review timestamp are null.
There is no score calculation, sign-off validator or automatic acceptance in this
skeleton. A fake output cannot prove factual support, even when it repeats a fixture.
Direct citation diagnostics are NOT APPLICABLE, not failed. RAG citation structure
and claim-to-supplied-evidence support belong in separate diagnostics/review fields.
Do not reuse retrieval Recall/MRR as answer correctness. Generated insufficiency is
not a verified unanswerable label; generation errors are not successful abstentions.

The empty scoring JSON requires manual editing/saving a separate reviewed copy;
there is no UI, autosave, submission or gold exporter. Keep it empty for this demo.
Actual QA references, including revised agricultural drafts, still require genuine
human approval before reference-dependent scoring. They are not loaded here.

QA-C1 PREPARATION — PROPOSED / UNAPPROVED, not a frozen scientific protocol

(IN-06/07/10/14, en/hi/hinglish), existing corpus/index identifiers and pinned
Qwen/MLX config identity. Identifiers/paths are metadata, not instructions to open
corpus files, encode passages, build an index or load a model. selected_retriever

instruction prefix and arm-specific source/citation rules have separate hashes.

Proposed budget: 12 Direct + 12 single-stage RAG calls, 384 maximum new tokens per

Equal call/output caps do not imply equal prompt tokens or total compute. Future

Attempt and denominator accounting
The proposal has 24 planned question-arm slots, zero actual model attempts and
zero simulated attempts. Its future token cap is not observed compute. The separate
synthetic demo consumes two supplied fake outputs; those are simulated attempts,
not actual calls. Never combine its numerator with the 24-slot proposal denominator.
account_fake_attempts validates a fixed case/language/arm plan; duplicate, unknown
or inconsistent observations fail. Missing observations become not_attempted slots.
The primary completion denominator is ALL planned slots, including failures and
unattempted slots. Also report simulated attempts and completions separately,
per-arm and paired-case. A completed malformed response counts as a completed
response, but not structurally valid. Runtime/length/repetition stops are incomplete
responses; their partial raw output remains retained. Structured-valid means
schema/status-valid BEFORE citation checks: an invalid citation can follow valid
structure but still suppress the answer. It is never a released valid draft.
Deliberate withholding (insufficient/uncertain), failure-suppressed answers, and
substantive answer drafts are separate counts. No failure is successful abstention;
no draft count establishes correctness. Human and reference-dependent scores stay
null. No automatic score/label conversion or human approval is implemented.

Blank rubric (options only, never preselected judgments)
A corpus-grounded support: fully supported / partially supported / unsupported
  by authorized corpus / uncertain-requires inspection.
B completeness: complete / partially complete / incomplete.
C corpus-relative answerability: appropriate answer / appropriate abstention /
  unsupported answer / incorrect withholding / uncertain.
D language: appropriate requested English/Hindi/Hinglish / partly appropriate /
  inappropriate or unintelligible.
E RAG supplied-evidence citation structure and separate human claim-to-evidence
  support. Direct supplied-evidence applicability is N/A; all human judgments
  (including citation judgments) remain null. Required facts, quantities/units
  and cultivation conditions have separate empty checks. Reference approval,
  reviewer identity, timestamp and approval fields remain empty.
Corpus-unsupported is not automatically externally false or hallucinated. Compare
content under the declared source-bounded task; do not penalize Direct for missing
citations to unseen evidence, or treat LLM self-evaluation as independent review.
